# Дизайн-система impact log

Живой гайд для разработки. Решение и мотивация — [ADR-0004](adr/0004-design-system.md).
Витрина компонентов: `pnpm dev` → http://localhost:5173/dev/ui.

## 1. Характер

Спокойный, «инженерный». Много воздуха, крупные плотные заголовки, карточки на мягком фоне, один зелёный акцент.
Моноширинный шрифт — как приправа: коды, ключи, метки, пасхалки (курсор `_` статуса сервера в футере).
Маскот — ретро-монитор с глазами — добавляет тепла, но не мешает работать.

## 2. Токены (`apps/web/src/styles/tokens.css`)

### Цвет
| Токен | Значение | Где |
|---|---|---|
| `--color-bg` | #f4f6f5 | фон приложения |
| `--color-surface` | #ffffff | карточки, поля |
| `--color-surface-muted` | #eef1ef | вторичные блоки, hover |
| `--color-glass` | белый 72% + blur | сайдбар, нижняя панель, всплывашки |
| `--color-text` / `-secondary` / `-muted` | #0f1a15 / #56605b / #8a938e | основной / пояснения / подписи |
| `--color-primary` | #0f1f18 | главные кнопки |
| `--color-accent` | #22c77a | фокус, активное, иконки, прогресс |
| `--color-accent-strong` | #129b5c | акцентный **текст** и ссылки (контраст ≥ 4.5) |
| `--color-accent-soft` | #e3f8ed | фон активного/выбранного, подложки иконок |
| `--color-surface-raised` | #ffffff / #2a3630 (тёмная) | «приподнятый» элемент поверх `--color-surface-muted` (выбранный сегмент `UiSegmented`) |
| `--color-danger` / `warning` / `info` (+ `-soft`) | | статусы и их фоны |

Правило: зелёный `--color-accent` не используем для текста на белом — только `--color-accent-strong`.
Текст на главной кнопке — `--color-on-primary` (в тёмной теме кнопка светлая, текст тёмный), на опасной —
`--color-on-danger`.

### Темы
- Светлая — значения в `:root`, тёмная — переопределения в `:root[data-theme='dark']` (там же тени).
- Атрибут `data-theme` ставит `public/theme-init.js` до отрисовки, дальше — `composables/useTheme.ts`.
  Переключатель `ThemeSwitcher` в шапках — светлая ⇄ тёмная; пока пользователь не выбирал, берётся системная тема.
  Выбор хранится в localStorage.
- В компонентах никаких цветов вне токенов — тогда тёмная тема работает автоматически.
  Исключения с комментарием: подложка QR-кода всегда белая (сканируемость), цвета маскота и логотипа.
- Проверяем каждый экран в обеих темах.

### Типографика
- Интерфейс — **Manrope**, моно — **JetBrains Mono**.
- Шкала: 12 / 13 / **15 (основной)** / 17 / 20 / 26 / 34 / 46 px (`--text-xs` … `--text-4xl`).
- Заголовки: `--weight-bold`, `--leading-tight`, `--tracking-tight` (−0.025em).
- H1 страницы: 34 → 46 px с tablet. H2 секции: 26 px. Заголовок карточки: 17 px.

### Отступы, скругления, тени
- Отступы — шаг 4px: `--space-1` (4) … `--space-16` (64). Внутри карточки 20/24 px, между секциями 48 px.
- Скругления: поля 12, карточки 20, крупные панели 28, кнопки и бейджи — «таблетка».
- Тени: `--shadow-sm` для карточек, `--shadow-md` для всплывашек, `--shadow-lg` для главной карточки
  экрана (форма входа), `--shadow-focus` — кольцо фокуса.

### Движение
- `--ease-out` для большинства переходов, `--ease-spring` для «живых» (крылья совы, облачко).
- 120 / 200 / 360 ms. Анимируем только `transform` и `opacity`.
- `prefers-reduced-motion` → длительности 0, анимации маскота выключены.

### Сетка
См. [ADR-0003](adr/0003-responsive-layout.md): mobile < 720 ≤ tablet < 1200 ≤ desktop; каркас 1200,
текст 720; `@media (--tablet)` / `(--desktop)`.

## 3. Каркасы страниц (`src/layouts`)

| Каркас | Где | Состав |
|---|---|---|
| `AppLayout` | приложение (вошедший пользователь) | сайдбар-«рельс» из иконок (tablet+), липкая шапка (заголовок, язык, пользователь, «Выйти»), контент, футер; на mobile вместо сайдбара — нижняя панель |
| `AuthLayout` | вход, регистрация | логотип + язык, по центру карточка с совой, мятный фон |
| `PublicLayout` | публичные страницы: посадочная `/`, «Принципы» (для гостей), 404 | шапка с «Вход/Регистрация» или «Открыть дашборд», футер |

`meta.layout: 'adaptive'` — App для вошедших, Public для гостей (так устроены «Принципы»).
Разделы без готовых страниц показываются в навигации приглушёнными с подписью «скоро».

Кнопки: одна primary на экран/форму. Разрушительные действия — `danger` + подтверждение.
Кнопка с `loading` не меняет ширину (текст скрывается, спиннер по центру).
Удаление записи подтверждается `UiDialog tone="danger"`, а сразу после — «Вернуть» в журнале (отмена лучше, чем
второе подтверждение).

Подписи шкалы — `impacts.score.1…5`, одинаковые с клиентами захвата (Chrome, CLI, VS Code).

### Горячие клавиши
Одиночные клавиши работают вне полей ввода и открытых диалогов, по физической клавише (и в русской раскладке).

| Где | Клавиша | Действие |
|---|---|---|
| Журнал | `N` | новая запись |
| Журнал | `/` | поиск |
| Запись | `E` · `←` `→` | редактировать · соседние записи |
| Форма записи | `⌘/Ctrl + Enter` · `Esc` | сохранить · отмена (с подтверждением, если есть изменения) |

## 5. Формы

**Разметка**
- Подпись **над** полем (не плейсхолдер вместо подписи). Подсказка под полем, при ошибке ошибка заменяет подсказку.
- Правильные `name`/`autocomplete` (`username`, `current-password`, `new-password`, `one-time-code`) — чтобы
  работали менеджеры паролей.
- Главная кнопка — `type="submit"` на всю ширину формы; Enter отправляет форму.
- `novalidate` на `<form>`: валидация наша, а не браузерная.

**Валидация** (`useZodForm`, схемы — `packages/shared`)
1. Поле проверяется при потере фокуса (пустое — не ругаем до отправки).
2. После первой ошибки поле перепроверяется на каждый ввод — ошибка исчезает, как только исправлено.
3. При отправке проверяется всё; фокус переходит на первое неверное поле.
4. Кнопку отправки **не** блокируем за невалидность — только на время запроса (`loading`).
5. Ошибка сервера — `UiAlert tone="danger"` над кнопкой; ошибка конкретного поля — под полем.
6. Тексты ошибок — ключи `validation.*` / `errors.<CODE>` в i18n, оба языка сразу.

**Коды 2FA**: `UiOtpInput`, автоотправка при вводе 6-й цифры; при неверном коде — поле очищается,
фокус возвращается, маскот огорчается.

**Длинные формы** (запись `ImpactForm`): те же правила валидации, но
- Enter в однострочном поле **не** отправляет форму (легко отправить недописанное) — только кнопка или `⌘/Ctrl+Enter`;
- панель действий липкая (над нижней навигацией на mobile), подсказка про `⌘/Ctrl+Enter` — на desktop;
- уход со страницы с несохранёнными изменениями (Esc, «Отмена», навигация) — через `UiDialog`; закрытие вкладки — `beforeunload`;
- ошибки вложенных полей — по «пути» (`metrics.0.value`), сообщения ядра (`impact.titleRequired`) → `validation.impact.*`.

## 6. Маскот

Ретро-монитор с глазами — персонаж impact log (`components/AppMascot` + контроллер `composables/useMascot`).
Светлый корпус на ножках-упорах, тёмный экран со сканлайнами, зелёные светящиеся пиксельные глаза, вместо рта —
мигающий курсор `_`, индикатор питания. Вся мимика — только на экране.
Цвета маскота фиксированы и одинаковы в обеих темах.

| Состояние | Когда |
|---|---|
| `watching` | фокус в поле логина; зрачки следуют за текстом |
| `hiding` | пароль или код 2FA — зажмуривается `> <` |
| `peeking` | пароль показан кнопкой «глаз» — один глаз зажмурен, другим подглядывает |
| `idle` | ничего не происходит; моргает, иногда наклоняется / подпрыгивает / оглядывается / экран «глючит» |
| `sleeping` | 45 секунд без активности: глаза-чёрточки, экран тускнеет, индикатор «дышит»; просыпается от мыши или клавиши |
| `happy` / `oops` | успешный шаг (глаза `^ ^`) / ошибка (красные `x x`) |

Реплики в облачке — `mascot.*` в i18n. Форма управляет совой только через контроллер
(`focus`, `blur`, `input`, `reveal`, `react`), не через классы.

## 7. Тексты и тон
- Коротко, по-человечески, без канцелярита. Обращение на «вы».
- **impact log** не переводится никогда (см. CLAUDE.md).
- Честно про ограничения: если функции ещё нет — «скоро», а не заглушка, притворяющаяся рабочей.

## 8. Чек-лист ревью UI
- [ ] Только токены: нет «сырых» цветов/размеров в CSS компонентов.
- [ ] Проверено на 375 / 720 / 1200, нет горизонтальной прокрутки.
- [ ] Проверено в светлой и тёмной теме.
- [ ] Фокус виден, интерактив доступен с клавиатуры, у иконок-кнопок есть `label`.
- [ ] Строки в `ru` и `en`.
- [ ] Состояния: загрузка, пусто, ошибка.
- [ ] `prefers-reduced-motion` не ломает экран.
