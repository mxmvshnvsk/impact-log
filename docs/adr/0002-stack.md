# ADR-0002: Технологический стек и структура кода

- Статус: принято
- Дата: 2026-09-27

## Решение

### Общее
- **Монорепозиторий на pnpm workspaces**:
  - `apps/web` — фронтенд (SPA);
  - `apps/api` — бэкенд (HTTP API);
  - `packages/shared` — общие zod-схемы, типы, коды ошибок. Одна схема валидирует форму на фронте
    и тело запроса на бэке.
- **TypeScript** везде, strict mode.
- **Biome** — линтер и форматтер (один инструмент вместо ESLint + Prettier).
- **Node.js 24 LTS**.

### Frontend (`apps/web`)
- **Vue 3** + **Vite**, Composition API.
- **Состояние**: `reactive`/`ref` и composables. **Pinia не подключаем**, пока не появится состояние,
  общее для многих несвязанных компонентов, — тогда Claude сообщает владельцу и подключаем по согласованию.
- **vue-router**, history mode (Caddy отдаёт `index.html` на неизвестные пути).
- **vue-i18n**: языки `ru` (основной) и `en`, все строки UI — только через ключи переводов.
- **zod** — валидация форм (схемы из `packages/shared`).
- **HTTP**: тонкая обёртка над `fetch`, без axios.
- **Sourcemaps**: генерируются в режиме `hidden` (файлы `.map` есть в сборке, но на них нет ссылок
  из бандла и Caddy их не отдаёт) — для отладки подключаются локально.
- UI-библиотека / стили — отдельное решение после сбора референсов дизайна.
- Контент записей — **Markdown** (textarea + превью), редактор развиваем позже.

### Backend (`apps/api`)
- **Fastify 5** + `fastify-type-provider-zod` (валидация и типизация запросов zod-схемами).
- Безопасность: `@fastify/helmet`, `@fastify/rate-limit`, `@fastify/cookie`.
- **PostgreSQL 17** + **Drizzle ORM** / drizzle-kit (миграции — SQL-файлы в репозитории).
- Полнотекстовый поиск — средствами Postgres (`tsvector`, конфигурации `russian`/`english`).
- Авторизация — собственная реализация по ADR-0001 на примитивах `@node-rs/argon2`, `@oslojs/otp`.
- API возвращает **коды ошибок**, а не тексты; перевод — на фронте.
- Dev: `tsx watch`; prod: бандл `tsup` (включая `packages/shared`).

### Почему не MongoDB
Данные реляционные (пользователь → записи → теги/проекты), дашборды — агрегации и группировки.
Postgres покрывает «много текста» (`text`, полнотекстовый поиск с морфологией, `jsonb` для гибких полей),
сохраняя JOIN, строгую схему и транзакции. Файлы хранятся не в БД.

### Тесты
До выхода из альфы автотесты не пишем. Исключения (рекомендация, на усмотрение владельца):
CI с первого дня проверяет lint + typecheck.

## Структура фронтенд-кода (для удобного ревью)

Вёрстка, логика и стили разделены по файлам. Компонент — это папка:

```
components/EntryCard/
  EntryCard.vue      — только <template> и тонкий <script setup>: props, emits, вызов composable
  useEntryCard.ts    — вся логика компонента (состояние, обработчики, вычисления)
  EntryCard.css      — стили, подключаются через <style scoped src="./EntryCard.css">
  index.ts           — реэкспорт компонента
```

Правила:
- `<script setup>` в `.vue` — не больше ~10–15 строк: объявление props/emits и
  `const { … } = useXxx(props, emit)`. Никакой бизнес-логики.
- Код, не зависящий от Vue (форматирование, парсинг, вычисления), — в `src/utils/*` чистыми функциями.
- Работа с API — в `src/api/*`; компоненты не вызывают `fetch` напрямую.
- Переиспользуемые composables — в `src/composables/*`.
- Страницы — в `src/views/<Name>/` по той же схеме.

Почему не `<script src="./X.ts">`: Vue не поддерживает внешний `src` для `<script setup>`, а классический
`setup()` с ручным `return` всех биндингов хуже читается. Схема «тонкий script setup + composable»
даёт то же разделение без этих потерь.
