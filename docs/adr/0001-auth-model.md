# ADR-0001: Модель аутентификации

- Статус: принято
- Дата: 2026-09-27

## Контекст
Сервис для разработчиков, хранит рабочие заметки. Цели: максимум безопасности, минимум персональных данных
(в т.ч. чтобы по возможности не обрабатывать ПДн в смысле 152-ФЗ), минимум «заморочек» для пользователя.

## Решение
1. **Без почты и телефона.** Идентификатор — логин (никнейм). Писем сервис не отправляет.
2. **Пароль**: минимум 12 символов, хеш Argon2id. Опционально — проверка по HIBP (k-anonymity).
3. **2FA (TOTP) обязательна.** Подключается на этапе регистрации: QR-код → подтверждение первым кодом.
   Без подтверждённой 2FA аккаунт не активируется.
   - TOTP-секрет хранится зашифрованным (ключ — в env сервера, не в БД).
   - Защита от повторного использования кода в пределах окна.
4. **Резервные коды**: 10 одноразовых кодов, показываются один раз при регистрации (скачать/скопировать,
   подтверждение «я сохранил»). В БД — только хеши. Можно перевыпустить (старые аннулируются).
5. **Восстановление доступа — только резервными кодами.** Потеря пароля/устройства и кодов = потеря аккаунта.
   Это явно сообщается при регистрации.
6. **Сессии**: cookie httpOnly + Secure + SameSite; список активных сессий, «завершить все остальные»;
   смена пароля или 2FA завершает все сессии.
7. **Защита от перебора**: rate limiting на логин и ввод 2FA (по логину и IP); одинаковые ответы
   для «нет пользователя» и «неверный пароль».
8. **Удаление аккаунта** — полное, с подтверждением паролем и 2FA. **Экспорт** всех данных (JSON/Markdown).
9. **Логи и трекинг**: IP в логах усечены, ротация 7–14 дней; без внешней аналитики; только сессионная cookie.

## Последствия
- (+) Почти нет ПДн; нет зависимости от почтового провайдера и SPF/DKIM.
- (+) Единый высокий уровень безопасности для всех аккаунтов.
- (−) Нет «забыл пароль» по почте — пользователь, потерявший коды, теряет аккаунт.
- (−) Чуть больше трения при регистрации и входе.

## Дополнение (2026-09-27): «Запомнить этот компьютер»
Осознанное послабление п. 3 по решению владельца (как у GitHub/Google):
- на шаге кода 2FA — флажок «Запомнить этот компьютер на 30 дней»;
- с флажком: полная сессия на 30 дней (постоянная cookie) и доверенное устройство — случайный токен в cookie
  `il_device` (HttpOnly, Secure, SameSite=Strict, Path=/api/auth), в БД `trusted_devices` — только SHA-256 и срок.
  При следующих входах с этого устройства пароль обязателен, код 2FA — нет;
- без флажка: сессия сутки (продлевается при активности), cookie без срока — удаляется при закрытии браузера;
- «Выйти везде» сбрасывает все сессии и все доверенные устройства;
- это не персональные данные: никаких отпечатков браузера, IP, названий устройств; техническая cookie,
  описана на странице «Принципы».

## Реализация (2026-09-27)
- API (`/api/auth`): `POST /register` → `POST /register/confirm`; `POST /login` → `POST /login/verify`
  (`method: totp | recovery`); `POST /logout`; `GET /me`.
- Сессия — cookie `il_session` (HttpOnly, Secure в prod, SameSite=Strict, Path=/api). В БД — SHA-256 токена.
  Виды сессии: `enrollment` (30 мин, регистрация до подтверждения 2FA), `second-factor` (5 мин, пароль верный,
  ждём код), `full` (сутки или 30 дней с «Запомнить этот компьютер», продлевается при использовании).
- Не больше 5 неверных кодов на сессию — дальше сессия сгорает (`SESSION_EXPIRED`).
- Лимиты частоты по IP: регистрация 5/час, вход 10/5 мин, коды 15 за 5–10 мин.
- CSRF: помимо SameSite=Strict изменяющие запросы принимаются только как `application/json`
  и с совпадающим `Origin`.
- TOTP: RFC 6238, 30 с, 6 цифр, SHA-1 (совместимо со всеми приложениями), допуск ±1 шаг;
  повтор кода отклоняется по `totp_last_step`. Секрет шифруется AES-256-GCM ключом `TOTP_ENCRYPTION_KEY`.
- Незавершённые регистрации и истёкшие сессии удаляются раз в час.
- Логин нормализуется в нижний регистр; проверка пароля для несуществующего логина выполняется «вхолостую»,
  чтобы время ответа не выдавало существование аккаунта.
