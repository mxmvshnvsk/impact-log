# PWA и офлайн-оболочка

impact log — local-first ([ADR-0005](adr/0005-local-first-e2ee-architecture.md)): записи зашифрованы и лежат в
IndexedDB браузера, сеть нужна только для синхронизации. Чтобы приложение **открывалось** без сети, web-клиент —
PWA: service worker хранит файлы приложения (оболочку), манифест позволяет установить impact log как приложение.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `apps/web/src/pwa/sw.ts` | service worker: кеш оболочки, стратегии запросов, сообщения от страницы |
| `apps/web/src/pwa/swBuildPlugin.ts` | Vite-плагин (только `build`, Node): собирает `/sw.js` из `sw.ts`, вписывает список файлов сборки и версию |
| `apps/web/src/pwa/update.ts` | регистрация service worker, проверка и применение обновлений (`usePwaUpdate`) |
| `apps/web/src/pwa/online.ts` | статус сети (`useOnline`, по `navigator.onLine`) |
| `apps/web/src/pwa/themeColor.ts` | `<meta name="theme-color">` = `--color-bg` выбранной темы (панель браузера, окно PWA) |
| `apps/web/src/pwa/protocol.ts` | типы сообщений страница ↔ service worker, имя кеша |
| `components/PwaOfflineBanner` | плашка «Нет сети — всё работает локально…» над каркасом страницы |
| `components/PwaUpdateToast` | тост «Доступна новая версия — Обновить» |
| `public/manifest.webmanifest` | манифест: «impact log», `start_url` `/dashboard`, `standalone`, иконки |
| `public/icons/*.png` | иконки 192/512 (`any` и `maskable`), `apple-touch-icon` 180 |
| `apps/web/scripts/pwa-icons.mjs` | генератор иконок: маскот-монитор без ножек, PNG пишется вручную (`node:zlib`) |

Плашка и тост подключены в `main.ts` (корневой компонент: плашка → `App` → тост), строки — namespace `pwa`.

## Что кешируется

Один кеш — `impact-log-shell-<версия>`, в нём **только файлы сборки приложения**: `index.html`, все js/css-чанки
(включая ленивые экраны и `kdf.worker-*.js`), шрифты, иконки, манифест, `theme-init.js`, `favicon.svg` — ровно то,
что лежит в `dist` (кроме `*.map` и самого `sw.js`). Список составляет плагин на этапе сборки; во время работы
service worker ничего нового в кеш не добавляет (только восстанавливает файл из этого списка, если браузер его
вытеснил).

Не кешируется и не перехватывается ничего другого: ответы API, записи, ключи, данные аккаунта. Запросы к `/api/*`
и к чужим источникам service worker пропускает мимо себя — `respondWith` для них не вызывается. Зашифрованные
записи живут в IndexedDB (хранилище vault) и к service worker отношения не имеют.

| Запрос | Стратегия |
|---|---|
| навигация (переход по адресу, перезагрузка) | сеть с таймаутом 3 с (с navigation preload) → при ошибке сети, таймауте или 5xx — `index.html` из кеша (SPA, дальше маршрут разбирает vue-router) |
| файл из списка сборки | кеш → при промахе сеть и дозапись в кеш |
| `/api/*`, не-GET, чужие источники, прочее | мимо service worker |

**Версия** — первые 16 символов sha256 от исходника `sw.ts`, имён и содержимого всех файлов сборки. Сборка
детерминированная: тот же код → побайтно тот же `sw.js` → браузер не видит обновления (например, при деплое,
где изменился только api). Изменился любой файл → новая версия.

При установке новой версии файлы с хешем в имени (`/assets/*`) берутся из кеша прошлой версии, если они там
есть, остальные (`index.html`, иконки, манифест) скачиваются мимо HTTP-кеша. При активации кеши прошлых
версий удаляются.

## Обновления

1. Браузер проверяет `/sw.js` при переходах; SPA переходов почти не делает, поэтому приложение само вызывает
   `registration.update()` раз в час, при возвращении на вкладку (не чаще раза в 15 минут) и при появлении сети.
2. Новая версия скачивается целиком в фоне и **ждёт** (`waiting`). Страница без спроса не перезагружается —
   пользователь может заполнять форму.
3. Во вкладке появляется тост «Доступна новая версия — Обновить». «Обновить» → `skipWaiting` → смена
   контроллера → перезагрузка (если в форме есть несохранённое, сработает её `beforeunload`). «Позже» — тост
   скрывается; новая версия включится сама, когда закроются все вкладки impact log.
4. Если вкладка **уже** работает на новой версии (после деплоя навигация прошла по сети и получила новый
   `index.html`), тоста нет: страница спрашивает ожидающий service worker, есть ли её входной скрипт в его
   оболочке, и при «да» активирует его тихо.
5. Другие открытые вкладки старой версии после активации новой получают тот же тост — им нужна перезагрузка.

Service worker регистрируется **только в production-сборке** (`import.meta.env.PROD`) и только если браузер его
поддерживает; иначе приложение работает как обычный сайт. На dev-сервер (`pnpm dev`) не влияет.

## Сервер (Caddy) и CSP

- `/sw.js`, `/manifest.webmanifest` и `index.html` — `Cache-Control: no-cache` (иначе новая версия может
  «застрять» в HTTP-кеше), `/assets/*` — `immutable`. Манифест отдаётся как `application/manifest+json`.
- CSP не менялась: `worker-src 'self'` разрешает регистрацию `/sw.js`, манифест подпадает под
  `default-src 'self'` (`manifest-src` не задан), иконки — под `img-src 'self'`. Service worker получает ту же
  CSP, его запросы — только к своему источнику (`connect-src 'self'`).

## Как сбросить

- **Пользователю** (что-то не обновляется): DevTools → Application → Service workers → Unregister и Cache storage →
  удалить `impact-log-shell-*`, затем перезагрузить страницу. **Не** нажимайте «Clear site data» / «Очистить
  данные сайта», если записи не синхронизированы и не экспортированы: вместе с кешем удалится IndexedDB с
  записями и ключ устройства.
- **Владельцу** (аварийно выключить PWA у всех): нельзя просто удалить `sw.js` — Caddy отдаст на этот путь
  `index.html` (SPA), проверка обновления упадёт, и старый service worker останется. Нужно выложить вместо
  него «самоудаляющийся» `sw.js`:

  ```js
  self.addEventListener('install', () => self.skipWaiting())
  self.addEventListener('activate', (event) => {
    event.waitUntil((async () => {
      for (const name of await caches.keys()) {
        if (name.startsWith('impact-log-shell-')) await caches.delete(name)
      }
      await self.registration.unregister()
    })())
  })
  ```

  и убрать регистрацию (`initPwa`) и плагин из сборки. IndexedDB с записями это не затрагивает.

## Проверка локально

```sh
pnpm --filter @impact-log/web build
pnpm --filter @impact-log/web preview   # http://localhost:4173 — service worker работает на localhost
```

DevTools → Application: Manifest (иконки, ошибки), Service workers, Cache storage. Офлайн — Network → Offline.
Сценарий: открыть приложение → «Начать без регистрации» → запись → офлайн → перезагрузить `/dashboard`,
открыть `/insights`, `/impacts/new`, `/review` — всё открывается, записи на месте, видна плашка; новая
сборка → `registration.update()` → тост.

Иконки перегенерировать (только если поменялся маскот): `node apps/web/scripts/pwa-icons.mjs`.

## Ограничения

- Первый заход требует сети: офлайн-оболочка появляется после того, как service worker скачал её (~1,4 МБ,
  в фоне после загрузки страницы).
- Safari (без установки на экран «Домой») может удалить данные сайта — и IndexedDB с записями — после 7 дней
  без посещений. Установка как приложения и синхронизация/экспорт от этого защищают; `navigator.storage.persist()`
  пока не запрашивается.
- `navigator.onLine === true` не гарантирует доступ к серверу («сеть есть, интернета нет»): плашка в этом
  случае не появится, а навигация откроет оболочку из кеша по таймауту.
- В приватном режиме некоторых браузеров service worker недоступен — приложение работает, но без офлайн-оболочки.
